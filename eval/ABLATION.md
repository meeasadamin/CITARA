## What the table says

- **The cross-encoder is what makes refusal possible.** Every configuration without it (dense, sparse, hybrid) answers all 6 questions the corpus cannot answer, while the configurations with it (hybrid + rerank, dense + rerank gate) answer none. This is not a tuning difference: reciprocal rank fusion produces scores derived from ranks, which carry no absolute meaning and cannot be thresholded, so a pipeline without the cross-encoder has nothing to refuse on. Its value here is a calibrated score, not better ordering.
- **That guarantee costs latency.** Gated configurations run at 3308 ms against 12 ms for retrieval alone, almost entirely cross-encoder inference on CPU. For a system whose worst failure is a confident wrong answer, that is a trade worth making.
- **Best retrieval quality: dense + rerank gate** at Hit@5 0.458 and MRR 0.255.
- **Hybrid fusion did not pay for itself.** Dense ranking reaches Hit@5 0.458 against 0.375 for even fusion, so BM25 is weighted out of the ranking by default. The specification argued the opposite; the measurement is what shipped. BM25 still runs and contributes candidates, and the per-category table shows why it is kept: it is the only retriever that can match an exact identifier.
- **Follow-up questions fail in every configuration**, including with model-based query rewriting active and producing well-formed standalone queries. The failure is therefore in retrieval rather than in rewriting, which is where the next round of work should go.

## What each configuration is for

- **dense** — Semantic search alone. Strong on paraphrase, structurally blind to exact tokens.
- **sparse** — BM25 alone. Finds identifiers a vector discards, misses everything worded differently.
- **hybrid** — Even reciprocal rank fusion of both retrievers, as the specification proposed.
- **hybrid + rerank** — Even fusion, then the cross-encoder scores the selected chunks.
- **dense + rerank gate** — Dense ranking with the cross-encoder as the refusal gate. The shipped default.

## Reading this honestly

The gold set holds 24 answerable questions, so a single question moves Hit@k by 0.042 and a two-question difference is within noise. These results are directional, and the ablation should be re-run as the set grows.

Hit Rate counts a question as found when a retrieved chunk covers a gold page. The relevance floor is disabled for the retrieval columns, because finding the evidence and deciding whether to answer are separate questions; the final column applies the shipped floor to the questions the corpus cannot answer.
